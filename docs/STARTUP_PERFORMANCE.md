# 桌面應用程式啟動效能改善方案

本文整理 RePDF 0.1.19 採用的做法，供其他 Python／Qt 桌面專案參考。

## 目前採用的方案

| 方案 | 實作方式 | 主要效益 |
| --- | --- | --- |
| 資料夾打包 | Windows 使用 PyInstaller `onedir`，以 ZIP 散布整個資料夾 | 將解壓成本移至使用者首次解壓，不再每次啟動支付 |
| 提前轉交既有視窗 | Windows 在載入 Qt、PDF、OCR 前，以原生 named pipe 傳送檔名 | 第二次啟動只需傳送要求，避免重複初始化 GUI 與後端 |
| 延後非必要載入 | 渲染程序在實際需要套用註解時才載入 pypdf 與註解寫入模組 | 減少後端啟動前必須完成的工作 |
| 常駐工作程序 | GUI 與預覽後端分離，多次要求重用同一個後端程序 | 不必為每頁預覽重新建立 Python、PDF 引擎與快取 |
| 封裝子程序共用環境 | 舊單檔模式下，工作程序沿用父程序的解壓環境，不強制重設 PyInstaller 環境 | 避免工作程序不必要地再次解壓；資料夾版則直接共用套件目錄 |

早期轉交目前使用 Windows 原生 API，不載入 Qt。其他平台仍使用原有 Qt 單一執行個體流程。移植至其他專案時，需依目標平台選擇 named pipe、Unix domain socket 等 IPC。

## 啟動流程

```text
啟動輕量入口
  ├─ 內部工作程序／自我檢查參數 → 各自專用入口
  └─ 一般啟動
       ├─ 成功聯絡既有視窗 → 傳送檔案、允許視窗取得前景、結束
       └─ 無既有視窗或轉交失敗
            → 載入 GUI → 以程序鎖再次確認單一執行個體
            → 啟動常駐後端 → 建立主視窗
```

早期檢查只是快速路徑，仍需保留正式程序鎖，處理同時啟動、伺服器尚未就緒與程序退出的競爭。傳輸應有長度限制、逾時與使用者存取限制；檔名應保留 Unicode、空白與多檔案順序。工作程序參數不可被一般開檔流程攔截。

## 穩定性改善：與效能改善分開看

- 工作程序先連線並送出已開始啟動的訊號，再載入大型模組，最後送出就緒訊號。
- 以總期限等待就緒，期間偵測子程序提前退出；RePDF 封裝版目前總期限為 120 秒。
- 啟動失敗時保留診斷輸出，終止殘留子程序，釋放程序鎖，並以 Qt 交談窗回報。

這些措施讓啟動失敗可診斷，避免把慢載入誤判為當機；提高逾時本身不會讓程式更快。

## 在其他專案的建議實作順序

1. 先量測：區分啟動器／解壓、模組載入、後端就緒、主視窗可見、首份文件可用。
2. 若單檔解壓占大宗，先改為資料夾版，安裝程式也可使用同一份資料夾產物。
3. 將參數解析與既有程序轉交移至最輕量入口；檢查其相依模組不會間接載入 GUI 或大型引擎。
4. 用 `python -X importtime` 找出載入成本，將非必要模組移至實際操作時載入。延後載入只是轉移成本，首次使用功能仍需載入。
5. 重用工作程序與有上限的資源快取，另設關閉、取消及錯誤復原流程。
6. 驗證封裝成品，而不只測原始碼；同時測試首次啟動、重複啟動與已有視窗時開檔。

## 量測方式與本次結果

使用外部計時器從啟動 EXE 開始計時，觀察程序樹與可見主視窗；已有視窗時，量測第二個啟動器傳送 PDF 並退出的時間。主視窗可見與文件完成渲染是不同指標。

2026-11-08 同機 Windows 單檔版對照：

| 指標 | 優化前兩次樣本 | 優化後兩次樣本 |
| --- | --- | --- |
| 主視窗可見 | 18.38／18.14 秒 | 13.12／13.02 秒 |
| 轉交既有視窗並退出 | 12.74／19.15 秒 | 10.37／15.16 秒 |

另一次打包形式對照中，單檔版為 15.48／16.29 秒，資料夾版為 9.64／6.36 秒。這是另一輪實驗，不應與上表混成同一組測試或將節省時間直接相加。

每項僅兩次樣本，受檔案快取、防毒掃描與系統負載影響，並非保證效能。其他專案應在同一台電腦交錯測量新舊版，記錄多次結果與中位數。

## 打包與更新注意事項

資料夾版需完整保留 EXE、`_internal` 與授權文件。更新前先關閉程式，替換整個資料夾，避免混用新舊 DLL。系統關聯與捷徑應指向固定位置的 EXE，搬移後需重新註冊。

目前沒有實作「單檔 EXE 的持久解壓快取」。若其他專案需要這種形式，快取檢查必須在大型套件解壓之前完成，並額外處理建置識別、完整性驗證、並行解壓與舊版本清理。

## 對照程式碼

- `src/repdf/entrypoint.py`：輕量入口與專用模式分派。
- `src/repdf/early_open.py`：不依賴 Qt 的 Windows 快速轉交。
- `src/repdf/desktop_open.py`：正式程序鎖與相容接收端。
- `src/repdf/backend_bootstrap.py`、`src/repdf/renderer.py`：後端握手、診斷與生命週期。
- `src/repdf/render_worker.py`：常駐渲染與按需載入。
- `packaging/repdf.spec`、`scripts/build_desktop.py`：資料夾打包、ZIP 與封裝自我檢查。
